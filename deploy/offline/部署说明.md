# 计划审核 · 公司服务器离线安装

适用 Linux x86_64 服务器，预装 Docker Engine、支持 `up --wait` 的 Compose v2，以及 flock、tar、gzip、sha256sum。包内含应用、MySQL 8.4.8 镜像、编译好的前端、锁定的 Python 依赖和三份空白 Excel（V3、V2、仅更新数量）。安装时由本地载入镜像。建议预留至少 4 GB 可用内存和 5 GB 可用磁盘，另留当前数据库、上传文件和备份所需空间。

## 更新已有离线安装

将新版解压到新的程序目录，保留旧程序目录。选维护时段，暂停上传和审批。在新版目录运行以下命令。以前指定过 `STATE_DIR` 时，两条命令都使用原路径。

```sh
sudo sh server.sh install
sudo sh server.sh status
```

脚本会先核验压缩包内部文件、载入镜像。发现应用版本变更时，会停止写入和数据库，将原数据、账号、附件和配置冷备到与状态目录同级的 `.backups` 目录，记录校验值，然后迁移并启动。默认冷备位置是 `/var/lib/easphub-plan-review.backups/`。冷备含生产密钥和业务数据，仅交授权人员保管。相同版本重复执行会继续使用已有配置。

数据库升级至 `0006` 后，一个账号对应一个业务角色。原有多个业务角色保留最高一项，原有仓库与密码保留。仅持旧技术角色或只读权限的账号标为停用，由管理员选定新角色后启用。已有标准和计划保留原版本；如果旧站仍使用 V2，由授权复审员从审核标准创建 V3 草稿并试算、发布。

## 首次安装

完整解压发布包，在解压目录执行：

```sh
sudo sh server.sh install
sudo sh server.sh status
sudo cat /var/lib/easphub-plan-review/secrets/initial-admin-password
```

首次安装会校验文件、导入镜像、初始化 MySQL、建立管理员账号并启动 web 和 worker。账号为 `admin`。初始密码仅保存在该服务器，首次登录后请在个人菜单修改。管理员通过「管理 → 人员与权限」设置计划员、复审员或管理员及其授权仓库。十个市场和欧洲通用 V3 标准随新库初始化，快照、计划和其他用户从空库开始。

## 公司同事的访问入口

服务默认仅在服务器的 `127.0.0.1:3350` 提供后端入口。请将公司已有的 **HTTPS** 域名接入反向代理，再把 `https://公司域名/apps/plan-review/` 发给同事。正式登录需要 HTTPS。

宿主机 Nginx 可将下列配置放在已有的 HTTPS server 中，然后用 `nginx -t` 检查并平滑重载：

```nginx
location = /apps/plan-review {
    return 308 /apps/plan-review/$is_args$args;
}
location ^~ /apps/plan-review/ {
    proxy_pass http://127.0.0.1:3350;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
    client_max_body_size 21m;
}
```

若公司 Nginx 本身在 Docker 内，首次安装时可指定它所在的用户定义网络：

```sh
sudo env PROXY_NETWORK=company-proxy sh server.sh install
```

在该代理的 HTTPS server 中包含本包 `deploy/nginx-location.company.conf` 的两个 location，然后验证和重载。文件中使用容器网络别名 `plan-review-company-web:3350`。服务器包会连接指定网络；对外域名、证书和代理配置由公司维护。MySQL 端口只在应用私有网络可用。

首次安装可用 `HTTP_PORT=13350` 指定空闲的本机端口。可用 `STATE_DIR=/srv/plan-review` 指定专用空目录，后续 start、stop、status、logs 均传相同的 STATE_DIR。宿主机 Nginx 请填写对应的本机端口。

## 运维

更新完成后检查 web、worker、database 健康状态，用原账号登录并核对历史计划、人员授权与模板下载。

```sh
sudo sh server.sh status
sudo sh server.sh logs
sudo sh server.sh stop
sudo sh server.sh start
```

定期冷备时执行 stop，备份完整状态目录及配置中引用的外部数据目录，保留属主与权限，然后执行 start。回退到升级前应使用对应旧版程序及当时冷备。先停止新服务，在受控位置保留新状态目录；在备份目录用 `sha256sum -c 备份文件名.sha256` 验证、用 `tar -tzf 备份文件名.tar.gz` 核对成员路径。从空的还原位置恢复到原绝对路径并保留属主与权限，使用原发行目录、原 STATE_DIR 运行 install。默认初始密码文件只用于首次登录。

公司服务器安装要求 root 或 sudo 权限；管理员、数据库密码均首次现场生成。工作电脑可直接通过浏览器访问公司域名。
